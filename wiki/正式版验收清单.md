# 正式版验收清单（30 分钟）

> 背景：2026-08-09 本机版本审查发现 4 个产品化缺口。本清单用于入职后拿到**正式版**时逐一验证——若新版已修复，则对应缺口自动关闭。预计 30 分钟跑完。每项结论写「已修复 / 仍缺失 / 部分」。

## 一、自动化配置（3 分钟）

| # | 验证项 | 操作 | 通过标准 |
|---|---|---|---|
| 1 | 定时任务能否在 UI 里换模型 | 打开任一自动化编辑页，找「模型」选择器 | 无需改数据库即可换 model_id |
| 2 | 自动化能否选自定义模型 | 模型下拉里找 `deepseek-v4-flash` | 自定义模型出现在选择器 |
| 3 | 自动化模型选择是否持久化 | 换模型保存后重启应用再查 | 重启后仍为所选模型 |

## 二、自定义模型接入（5 分钟）

| # | 验证项 | 操作 | 通过标准 |
|---|---|---|---|
| 4 | 有无可视化「添加自定义模型」向导 | 设置 → 模型 → 添加自定义 | 有表单而非手写 JSON |
| 5 | 文档站有无 models.json schema 页 | 翻 WorkBuddy 文档，搜「custom model / models.json」 | 有官方字段说明 |
| 6 | key 错误提示是否友好 | 故意填错 key 触发一次调用 | 报错指明「key 无效」，而非静默失败 |

## 三、专家 / 插件状态（5 分钟）

| # | 验证项 | 操作 | 通过标准 |
|---|---|---|---|
| 7 | enabledPlugins 开关与会话行为一致 | 关闭某专家插件后开新会话 | 该专家确实不可选；开启后可选 |
| 8 | 常驻专家自动加载 | 设置常驻后新建会话 | 专家默认生效，无需每次手动选 |

## 四、自动化可靠性（10 分钟）

| # | 验证项 | 操作 | 通过标准 |
|---|---|---|---|
| 9 | 关机/离线期间任务行为 | 关闭应用到下次预定运行时间再打开 | 任务有明确说明：补跑 / 跳过 / 顺延，且行为符合预期 |
| 10 | 失败重试与告警 | 人为让任务失败一次（如断网） | 有错误日志可查，非静默 |
| 11 | 运行历史可见性 | 查看自动化执行历史 | 有历史列表、耗时、token、模型记录 |

## 五、本地环境适配（5 分钟）

| # | 验证项 | 操作 | 通过标准 |
|---|---|---|---|
| 12 | 是否自动兼容代理环境 | 不配 git 代理直接 push 到 GitHub | 成功（说明已修复）或仍有文档指引 |
| 13 | 海外服务连通性 | 在代理环境下访问 GitHub / 海外 API | 有明确指引，不再需要手工踩坑表 |

## 附录：对应售中话术映射（仍缺失时怎么讲）

| 缺口 | 客户视角问题 | 建议话术 |
|---|---|---|
| 自动化模型要改 DB | 「换模型要不要找你们开发？」 | 「模型已按企业标准预置，变更走我们交付团队，一次配置长期运行」 |
| 无自定义模型文档 | 「配置依据什么？」 | 「自定义模型接入我们提供驻场配置服务，避免客户自行摸索」 |
| 本地依赖自动化 | 「关机了预警还发吗？」 | 「桌面端任务建议搭配云侧巡检；我们按您环境给最优部署形态」 |
