# 归档机制（自动化产出如何进入本 Wiki）

> 本页说明四个定时任务的产出是如何自动写入本 Wiki 的。**如果归档链路出问题，先看这一页。**

## 一、为什么 wiki 在仓库的 `wiki/` 目录，而不是 GitHub 的 Wiki tab

两个硬约束导致官方 Wiki tab 无法自动化：

1. **Wiki 的 git 后端（`<repo>.wiki.git`）只有在网页端手工创建过第一个页面后才存在。** 在此之前 `git ls-remote` 返回 `Repository not found`，无法 clone/push 初始化。
2. **GitHub 已下线 Wiki 页面的 REST API**（`POST /repos/{owner}/{repo}/wiki/pages` 返回 404），无法用 API 建页。

因此当前方案：**Wiki 内容作为仓库内的 `wiki/` 目录管理**。好处是全自动、有 PR/diff/history、可被 CI 校验。
若日后需要真正的 Wiki tab，只需在网页端手工建一页，把归档目标从 `wiki/` 切到 `<repo>.wiki.git`，**分类结构不变**。

## 二、为什么用 `gh` 而不是 `git push`

> **⚠️ 本节已于 2026-08-04 更正。早期结论「本机 git 不可用」是误诊，勿再据此排障。**

### 真实原因（已定位）

git 连 GitHub 失败有**两个叠加**的原因，都不是"代理服务器挂了"这么简单：

1. **环境变量注入**：运行环境注入了 `HTTP_PROXY` / `HTTPS_PROXY = http://127.0.0.1:56068`。git 会自动读取，从而走一个不通的代理。
2. **HTTP/2 framing 错误**：即使绕过代理，默认 HTTP/2 也会报 `Error in the HTTP2 framing layer`。

### 修法（一次性，已写入仓库 local config）

```bash
git config --local http.proxy ""          # 空值可覆盖环境变量，优先级高于 env
git config --local http.version HTTP/1.1  # 规避 HTTP/2 framing
```

配置后 `git fetch` / `reset` / `push` **全部正常**，无需每次 `env -u HTTP_PROXY ...`。

### 那为什么归档还是用 `gh`？

不是因为 git 不能用，而是因为对"追加一个章节"这件事，`gh` + Contents API **本身更合适**：

| | `gh` Contents API | `git clone/push` |
|---|---|---|
| 是否需要落地整个仓库 | 否，单文件读写 | 是，每次 clone/pull |
| 并发冲突 | 靠 `sha` 乐观锁，冲突可重试 | 需 rebase，易脏 |
| 失败面 | 一次 HTTP 调用 | clone→改→commit→rebase→push 多环节 |
| 受代理/HTTP2 影响 | 否 | 需先修 config |

**结论**：定时任务归档继续用 `gh`；人工维护仓库（改专家包、调结构）正常用 `git`。

## 三、归档脚本

路径：`scripts/commit_wiki.py`（本机副本：`~/.workbuddy/scripts/commit_wiki.py`）

```bash
python3 commit_wiki.py <repo> <page_path> <section_file> [commit_message]

# 示例
python3 ~/.workbuddy/scripts/commit_wiki.py \
  sudotty/traffic-operator-experts \
  wiki/每日AI网感雷达.md \
  /tmp/toe_section.md \
  "wiki(雷达): 2026-08-04 每日产出"
```

行为：
- `GET` 当前页面 → base64 解码 → **追加**新 section → `PUT` 回写（带 `sha`）。
- 页面不存在时自动**创建**（不带 `sha` 的 `PUT`）。
- 并发写入冲突（HTTP 409/422）自动重取 `sha` 重试，最多 3 次。
- `section_file` 为空时直接退出 0（**不产生空提交**）——"无异常不写入"的预警任务依赖此行为。

### 易踩的坑（已在脚本中处理）

| 坑 | 现象 | 正确做法 |
|---|---|---|
| `gh api` 的退出码 | HTTP 404/409 时退出码一律是 **1**，不是状态码 | 从 stderr 解析 `(HTTP \d{3})` |
| 建文件用 POST | Contents API 不接受 POST | 建/改**都用 `PUT`**，靠有无 `sha` 区分 |
| 中文内容传参 | 命令行转义易出错 | 写临时 JSON 文件后用 `gh api --input` |
| git 走了注入的死代理 | `Empty reply` / `CONNECT tunnel failed 502` | `git config --local http.proxy ""` |
| HTTP/2 协商失败 | `Error in the HTTP2 framing layer` | `git config --local http.version HTTP/1.1` |
| macOS 无 `timeout` 命令 | `command not found` | 改用后台运行 + 轮询 |
| zsh 下 git 触发 pager | 命令退出码 137、输出为空 | `GIT_PAGER=cat` 或 `--no-pager`，或重定向到文件 |
