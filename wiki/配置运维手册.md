## 一、models.json 字段说明（自定义模型注册）

文件：`~/.workbuddy/models.json`（JSON 数组，一个元素 = 一个自定义模型）。字段：

| 字段 | 必填 | 说明 | 当前值（deepseek-v4-flash） |
|---|---|---|---|
| `id` | 是 | 模型唯一 ID；**自动化 `model_id` 必须与此一致** | `deepseek-v4-flash` |
| `name` | 否 | 显示名 | `DeepSeek-V4 Flash` |
| `vendor` | 是 | 厂商标识 | `DeepSeek` |
| `url` | 是 | OpenAI 兼容 chat/completions 端点 | `https://api.deepseek.com/chat/completions` |
| `apiKey` | 是 | 明文 API key | sk-bdad…（勿外泄） |
| `supportsToolCall` | 是 | 是否支持 function calling | `true`（DeepSeek 官方支持 Tool Calls ✓） |
| `supportsImages` | 是 | 是否支持图像输入 | `false`（v4-flash 官方无视觉能力，正确） |
| `supportsReasoning` | 是 | 是否支持思考模式 | `true` |
| `reasoning.defaultEffort` | 否 | 默认思考强度 | `high` |
| `reasoning.supportedEfforts` | 否 | 可选强度列表 | `["high","max"]`（实测 `reasoning_effort:max` 官方接受） |

**核实纪律**：vendor 官方能力表变化（新增视觉 / tool call 等）时，先查官方文档再改对应布尔位，禁止凭印象。

## 二、自动化模型修改 SOP（工具接口不暴露 model 字段）

`automation_update` 工具只能改 name/prompt/rrule/status 等，**改 `model_id` 必须直接操作 DB**：

```bash
# 查看当前所有自动化及其模型
sqlite3 ~/.workbuddy/workbuddy.db "SELECT id, name, model_id, model_is_thinking, rrule FROM automations WHERE deleted_at IS NULL;"

# 改模型（示例：把某自动化改为 deepseek-v4-flash）
sqlite3 ~/.workbuddy/workbuddy.db "UPDATE automations SET model_id='deepseek-v4-flash', model_is_thinking=1, updated_at=strftime('%s','now')*1000 WHERE id='<AUTOMATION_ID>';"
```

注意：
- `model_is_thinking=1` 开思考模式（DeepSeek 默认 thinking enabled）。
- 改完务必 `SELECT` 复核。
- **平台内置模型**（如 `hy3-preview-agent`、归因侦探用的 `deepseek-v4-pro`）不需要出现在 models.json 里；`models.json` 只注册「用户自定义」模型。判断一个 model_id 是否有效：查官方 API `GET /models` 或用该 ID 发一次最小请求。

## 三、git 连 GitHub（本机必须显式代理）

**真因**：环境注入 `HTTP_PROXY/HTTPS_PROXY=http://127.0.0.1:7897`；git 若置空 proxy 直连会超时（Couldn't connect to server）。

```bash
git config --local http.proxy "http://127.0.0.1:7897"
git config --local http.version HTTP/1.1
# 远端领先时：先 git pull --rebase 再 push
```

npm 无代理配置可直连；`gh` CLI 可用。
