# 系统生命周期总纲（19 环节闭环 · 智能体系统架构）

> 定位：本专家系统的**最高层架构**——一条 19 环节的完整闭环：`GOAL → CONTEXT → STATE → MODEL → DECISION → ACTION → WORLD → EVIDENCE → VERIFICATION → REPAIR → TRACE → EXPERIENCE → MEMORY → SKILL → OPTIMIZATION → EVALUATION → RELEASE → BETTER SYSTEM → (回到 GOAL)`。
> 本质：**单次任务循环（前 11 环：OODA + PDCA 融合）× 长期学习循环（后 7 环：经验→技能→系统进化）** 的叠加。每一环都对应本库的既有文件或新增协议。
> 用法：任何全轨任务开始时，把本总纲当作「系统检查单」——确认每一环有对应物；弱环（STATE/REPAIR/TRACE/EXPERIENCE）按本文档新增协议执行。
> 版本：v2.2（2026-08-10）

## Part 1｜前 11 环 = 单次任务循环（OODA × PDCA 融合详解）

> 这 11 环是一次「从目标到修复」的完整任务执行，对应 OODA（Observe-Orient-Decide-Act，环 7/3/4/5-6）与 PDCA（Plan-Do-Check-Act，环 1-2-6-9-10）的融合。

### 环 1 GOAL · 目标
- **5W2H**：What=本次要达成的结果（被引用/排名/点击/转化/品牌词）；Why=北极星对齐（AI 引用率>品牌词>转化>打开率）；When=每个任务开始前；Where=协议 1 目标界定；Who=操盘手；How=SMART 化目标（具体/可测/可达/相关/有时限）；How much=量化目标（如"3 个月 AI 引用率 0→15%"）。
- **麦肯锡**：金字塔顶层——所有下级环节服务于 GOAL；So What：无目标则一切动作是噪音。
- **比喻**：目的地——没有目的地，再好的车也到不了任何地方。
- **对应文件**：协议 1 / benchmarks 北极星。

### 环 2 CONTEXT · 上下文
- **5W2H**：What=任务成立的边界条件；Why=条件不同方案不同（业务坐标路由）；When=目标确定后；Where=playbooks 三维（平台×阶段×变现）；Who=操盘手；How=列出关键假设+缺失信息；How much=假设清单 3-5 条、缺失信息逐条标注"是否改变方向"。
- **麦肯锡**：MECE 检查假设清单（互斥穷尽）；So What：假设错了，方案全错（Context 是决策的地基）。
- **比喻**：地形图——同样一支军队，山地和平原打法完全不同。
- **对应文件**：playbooks / 协议 1。

### 环 3 STATE · 状态（新增协议）
- **What**：当前系统处于什么状态（账号生命周期阶段 × 资源余量 × 战场态势）。
- **Why**：兵法"因势利导"——不判状态就决策=蒙眼开车；孙膑先判主客（客主人分）再定打法。
- **When**：每次任务开始时 + 每周归因时更新。
- **Where**：账号基线 schema 扩展。
- **Who**：操盘手。
- **How**：**账号状态机**——五态：`0-1 冷启动 → 验证期（找重复模式）→ 成长期（放大验证模式）→ 稳定期（守品牌+攻增量）→ 衰退/转型期（积疏监测触发）`。
- **How much**：状态判定标准——冷启动（无数据/<10 篇）、验证期（10-30 篇有 1-2 个重复模式）、成长期（模式验证+引用率上升 2 个月）、稳定期（引用率平台）、衰退（引用率/流量连降 2 月）。
- **麦肯锡**：MECE——五态互斥；So What：状态决定打法（冷启动=蓄势/验证期=聚焦实验/稳定期=正奇相生）。
- **比喻**：游戏存档——不知道存档在哪（状态），就无法决定下一步往哪走。
- **新增字段**：account-profile-schema.md 增加 `state` 字段（五态之一）+ `state_evidence`（判定依据）。

### 环 4 MODEL · 模型
- **What**：用哪套心智模型做判断（决策模型 × 概念体系 × 兵法法则）。
- **Why**：模型决定看见什么（你的心智模型=你的滤镜）；OODA 的 Orient 环节。
- **When**：任何判断前；Where=MODEL 层三个库。
- **Who**：操盘手；How=按问题类型选模型（评分卡→决策模型；概念解释→concept-hierarchy；战略推演→sunbin-core）。
- **How much**：模型选择 30 秒内完成（不纠结）。
- **麦肯锡**：模型即 MECE 的分类器——不同问题用不同模型，禁止一套模型打天下。
- **比喻**：眼镜——不同度数看不同距离，戴错眼镜全模糊。
- **对应文件**：decision-models / concept-hierarchy / sunbin-core / first-principles。

### 环 5 DECISION · 决策
- **What**：在选项间做选择（做哪个选题/攻哪个词/用什么形态）。
- **Why**：决策质量=信息×模型×时机；评分卡把决策从直觉变可复算。
- **When**：MODEL 选定后；Where=评分卡/三档预期/兵法推演。
- **Who**：操盘手；How=评分可见（因子取值+理由）+ 三档预期 + 兵法法则校验。
- **How much**：选题分阈值（≥7 支柱/4-7 卫星/<4 放弃）；三档预期必带触发条件。
- **麦肯锡**：金字塔——决策=结论，支撑=评分+依据；So What：每个决策都能被追问"凭什么"。
- **比喻**：菜谱——照着菜谱（公式）做，任何人都能做出 80 分的菜。
- **对应文件**：decision-models / sunbin-core（攻虚/雄牝城）。

### 环 6 ACTION · 行动
- **What**：把决策变成具体动作（写文/发布/分发/迭代）。
- **Why**：决策不落地=空谈；产线 8 环的 Act 面。
- **When**：决策后立即；Where=产线 8 环（定位→挖词→内容簇→钩子→成文→校验→分发→回流）。
- **Who**：产线各角色；How=按 8 环执行 + 输出规范（信号卡/三层表达）。
- **How much**：每环有产出物（关键词地图/大纲/成稿/校验报告）。
- **麦肯锡**：MECE——8 环互斥穷尽；So What：行动要有可验证的产出物。
- **比喻**：行军——命令（决策）下了，队伍（内容产线）按队形（8 环）走。
- **对应文件**：agent 产线 8 环 / output-spec。

### 环 7 WORLD · 世界
- **What**：真实世界对行动的反馈（发布后数据/竞品反应/平台变化）。
- **Why**：世界是唯一的真相来源（实测>推算）；"你可能都对，但市场说了算"。
- **When**：发布后 24-72h（L0 战术）；Where=发布平台/搜索引擎/AI 引擎。
- **Who**：系统（被动接收）；How=数据回流（打开/完读/分享/引用）。
- **How much**：单篇 24-72h 数据窗口。
- **麦肯锡**：Why So——所有模型/决策最终用 WORLD 反馈校验。
- **比喻**：回声——你喊什么（ACTION），山（WORLD）回什么；不听回声的喊叫是浪费嗓子。
- **对应文件**：L0 战术 OODA Observe。

### 环 8 EVIDENCE · 证据
- **What**：从 WORLD 反馈中提取结构化证据（引用率/排名/转化/竞品占位）。
- **Why**：原始数据≠证据——证据是"带口径的可解释数据"；活数据协议保证不编造。
- **When**：数据回收窗口后；Where=geo-monitoring 自测/Share of Visibility/活数据协议。
- **Who**：操盘手；How=多引擎多次测量（7-8 次重复）+ 四维记录（引擎/时间/query/结果）。
- **How much**：每 query 7-8 次重复；记录引擎+时间戳。
- **麦肯锡**：So What：证据要能支撑决策（无证据的结论=猜测）。
- **比喻**：体检报告——不是感觉，是数据；且要"多次测量"（一次血压不准）。
- **对应文件**：geo-monitoring / live-data-protocol / benchmarks（Share of Visibility）。

### 环 9 VERIFICATION · 验证
- **What**：证据是否支撑决策？结果是否达到 GOAL？
- **Why**：防自欺（确认偏误）；红队三视角+评估基准。
- **When**：证据收集后；Where=红队/evals/output-spec 验证清单。
- **Who**：操盘手（自我红队）+ 质检角色；How=三视角攻击+对照验证清单。
- **How much**：红队任一不过返工；验证清单逐条过。
- **麦肯锡**：Why So——每个结论自问"凭什么"；So What——验证不过的结论不能进 MEMORY。
- **比喻**：质检员——出厂前检查，不合格返工；不检查就发货=砸招牌。
- **对应文件**：decision-models 红队 / evals / output-spec 第九节。

### 环 10 REPAIR · 修复（新增协议）
- **What**：验证失败后如何最小代价修正（不是推倒重来）。
- **Why**：Tian 研究——定向修复改 5% 内容 +40% 引用率，全量重写改 5 倍内容更差；修复优先于重写是 2026 GEO 的确定性结论。
- **When**：验证失败时；Where=内容/策略/流程三个层面。
- **Who**：操盘手+产线；How=**修复协议四步**：①诊断定位（最弱环：检索/选中/归因 or 内容/策略/流程）②最小改动（改 5% 而非重写）③复测验证 ④记录（进 TRACE+EXPERIENCE）。
- **How much**：修复改动 ≤10% 内容；修复后 72h 复测。
- **麦肯锡**：MECE——先定位哪个层面坏了，再修；So What：修复要可验证（修前修后对比）。
- **比喻**：修车 vs 换车——轮胎漏气补胎（修），不是换发动机（重写）；补不好才考虑换。
- **对应文件**：新增（本文档 §10）/ 引用 Tian arXiv:2603.09296。

### 环 11 TRACE · 追溯（新增协议）
- **What**：每个决策/修复留下可审计的追溯链（从 GOAL 到 ACTION 的完整证据链）。
- **Why**：可追溯=可审计=可信任；执行溯源（arXiv:2606.04990）——"能被溯源才值得信任"；AI 归因同理。
- **When**：每个全轨任务全程；Where=任务日志/记忆文件。
- **Who**：系统（自动记录）；How=**追溯格式**：`任务ID → GOAL → 决策（含评分）→ ACTION → EVIDENCE → VERIFICATION → REPAIR（若有）→ 结果`。
- **How much**：每个全轨任务 1 条追溯记录（≤15 行）。
- **麦肯锡**：So What：追溯是记忆的前提（无追溯的经验=无法复用的经验）。
- **比喻**：黑匣子——飞机出事查黑匣子；任务失败查追溯链。
- **对应文件**：新增（本文档 §11）/ 工作区记忆日志。

## Part 2｜后 8 环 = 长期学习循环（经验→技能→系统进化）

### 环 12 EXPERIENCE · 经验（新增协议）
- **What**：从任务结果中提炼可复用经验（什么有效/什么无效/为什么）。
- **Why**：失败清单驱动（兵失/将败）——经验是系统进化的原材料；无提炼则每个任务从零开始。
- **When**：每周归因 + 每个任务收尾；Where=经验提炼。
- **Who**：操盘手；How=**经验提炼协议**：①记录（发生了什么+结果）②归因（为什么：选题/表达/环境层）③泛化（可复用到哪类场景）④沉淀（进 MEMORY/SKILL）。
- **How much**：每周 ≥1 条经验（含成功+失败各至少 1 条）。
- **麦肯锡**：MECE——成功经验/失败经验分库；So What：经验要能指导未来决策（否则是故事不是经验）。
- **比喻**：日记 vs 复盘——日记记流水账（记录），复盘提炼规律（经验）；复盘才有价值。
- **对应文件**：新增（本文档 §12）/ attribution-rhythm。

### 环 13 MEMORY · 记忆
- **What**：把经验结构化存储（账号基线/工作区记忆）。
- **Why**：跨会话连续性的唯一机制（越用越准）；记忆迭代 JSON Schema。
- **When**：每周归因 + 任务收尾；Where=账号基线 schema/工作区记忆。
- **Who**：系统（自动写）；How=按 schema 写（定位/历史指标/已验证模式/校准权重/内容矩阵/看板）。
- **How much**：记忆更新频率=每周；字段完整。
- **麦肯锡**：So What：记忆要可检索（结构化）——非结构化的记忆=找不到的文件。
- **比喻**：图书馆 vs 垃圾桶——结构化分类的才叫图书馆；乱塞的叫垃圾桶。
- **对应文件**：account-profile-schema / 记忆系统。

### 环 14 SKILL · 技能
- **What**：把验证有效的经验固化为可复用能力（本库文件/规则）。
- **Why**：经验→技能=个人能力→组织能力（把操盘手经验变成公司资产）；本会话的版本线（v1.6→v2.2）即此环。
- **When**：经验验证有效后；Where=skill 更新机制。
- **Who**：操盘手（执行）+ 系统（沉淀）；How=新增/修改 references + SKILL 注册 + 同步重装。
- **How much**：验证有效才入 skill（无效经验不入库，避免污染）。
- **麦肯锡**：So What：技能库是系统的"武器库"——不更新的武器库=废铁库。
- **比喻**：武功秘籍——打赢的招式（验证有效）才写进秘籍；瞎编的招式写进去害人。
- **对应文件**：本库全部（版本线机制）。

### 环 15 OPTIMIZATION · 优化
- **What**：用积累的数据校准模型权重与阈值。
- **Why**：默认权重是经验值，账号数据是真相——校准让模型更准（OODA Orient）。
- **When**：每周归因时；Where=权重校准（评分卡权重/阈值）。
- **Who**：操盘手；How=对照历史数据调权重，并显式标注「基于账号 X 数据，已将 Y 权重从 A 调至 B」。
- **How much**：每周校准 1 次；每次标注依据。
- **麦肯锡**：Why So——校准要有数据依据（不是拍脑袋调）；So What：校准后的模型=更准的决策。
- **比喻**：调音——乐器（模型）每次演出后微调；不调音越弹越跑调。
- **对应文件**：account-profile-schema 校准纪律。

### 环 16 EVALUATION · 评估
- **What**：系统整体质量评估（回归测试/看板指标）。
- **Why**：防退化——改一个文件破坏了另一个（回归）；Gartner：有自动评估回滚率 9% vs 无评估 47%。
- **When**：每次 skill 变更后 + 月度；Where=evals 14-prompt 回归 + 指标看板。
- **Who**：质检角色；How=跑回归测试集 + 看板趋势。
- **How much**：每次变更后回归全绿；月度看板复盘。
- **麦肯锡**：So What：评估是 RELEASE 的门禁（不合格不放行）。
- **比喻**：出厂检验线——每件产品（每次变更）过检才放行；跳过检验=赌运气。
- **对应文件**：evals / 指标看板。

### 环 17 RELEASE · 发布
- **What**：把验证过的技能更新发布上线（同步副本/重建 zip/git push）。
- **Why**：不发布=改了自己看（技能没生效）；发布是价值兑现。
- **When**：评估通过后；Where=安装版本/源仓库/副本。
- **Who**：系统（执行）；How=同步源仓库→副本→重建 zip→git push。
- **How much**：副本 diff 全一致；push 成功。
- **麦肯锡**：So What：发布有版本号（可回溯）；Why So：可回滚（发布错误能退）。
- **比喻**：软件发版——版本号+发布说明（changelog）+可回滚；不发版=代码躺硬盘。
- **对应文件**：本会话的同步重装流程。

### 环 18 BETTER SYSTEM · 进化
- **What**：整个系统比上一个循环更好（版本线演进）。
- **Why**：进化的标志=系统能力提升（不是文件变多）；每轮循环回答"系统强在哪了"。
- **When**：每个 RELEASE 后；Where=版本线（v1.x→v2.x）。
- **Who**：操盘手+系统；How=记录版本变更（本次新增/强化/修复）。
- **How much**：每轮 RELEASE 有版本增量（v2.1→v2.2 等）。
- **麦肯锡**：So What：进化要可感知（能力增强可演示）；Why So：没有进化的循环=空转。
- **比喻**：升级 vs 换新——系统在原有基础上升级（复用经验），不是每次推倒重来。
- **对应文件**：版本线记录 / 记忆日志。

### 环 19 → GOAL · 闭环
- **What**：带着新能力设定新目标，循环重启。
- **Why**：闭环是系统持续进化的引擎（OODA 转起来才有生命力）。
- **How**：BETTER SYSTEM 的新能力 → 新 GOAL → 新 CONTEXT → …
- **比喻**：年轮——每轮循环留下一圈年轮（经验/技能），树（系统）越长越粗。

## Part 3｜弱环补齐协议（本次新增）

### §3 STATE 账号状态机（协议）
```
五态判定（每次任务开始时 + 每周归因时）：
S1 冷启动：发布 <10 篇 或 无稳定数据 → 打法：蓄势（法则1）+ 聚焦实验（法则4）
S2 验证期：10-30 篇，出现 1-2 个重复模式（标题/选题被数据验证）→ 打法：放大验证模式
S3 成长期：模式验证 + 引用率环比上升 2 个月 → 打法：正奇相生（法则9）+ 攻虚（法则2）
S4 稳定期：引用率平台期 → 打法：守品牌（法则3）+ 找新奇
S5 衰退/转型：引用率/流量连降 2 月（积疏监测触发）→ 打法：诊断（兵失）+ 转型新坐标
判定证据：发布数/引用率/重复模式数（各态需可量化证据，禁止凭感觉判态）
```

### §10 REPAIR 修复协议
```
四步：①诊断定位（最弱环：内容/策略/流程 × 检索/选中/归因）②最小改动（≤10% 内容）
③复测验证（72h 后对照）④记录（进 TRACE + EXPERIENCE）
铁律：先修后写（Tian：修复改 5% 内容 +40%，全量重写改 5 倍更差）；修复不过再考虑重写
```

### §11 TRACE 追溯格式
```
【TRACE 任务ID】
GOAL: <目标>
DECISION: <决策 + 评分依据>
ACTION: <动作 + 产出物>
EVIDENCE: <数据 + 口径 + 引擎/时间>
VERIFICATION: <结果 ± 红队发现>
REPAIR: <若失败：诊断 → 最小改动 → 复测结果>
EXPERIENCE: <提炼的经验（成功/失败）>
（每任务 1 条，≤15 行，存工作区记忆）
```

### §12 EXPERIENCE 经验提炼协议
```
四步：①记录（发生了什么 + 结果）②归因（选题层/表达层/环境层，attribution-rhythm 三层归因）
③泛化（可复用到哪类场景）④沉淀（进 MEMORY 账号基线 / SKILL 规则）
铁律：验证有效才入 SKILL（避免污染）；失败经验进失败清单（兵失）防复发
```

## 与既有体系的关系
- **本文件是最高层架构**：19 环节是系统运行的「骨架」，其余文件是各环节的「器官」。
- 弱环补齐后，系统从「强在决策」升级为「全链路闭环」——每一环都有协议，无断点。
- 三条主线融合：三层 OODA（时间尺度）× 19 环生命周期（系统架构）× 3 尖刀（能力定位）——OODA 是运行时，生命周期是架构，尖刀是定位。
