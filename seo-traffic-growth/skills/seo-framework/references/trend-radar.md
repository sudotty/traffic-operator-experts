# 网感雷达（写稿前的活模式扫描）

> 解决问题：网感是 zeitgeist——本周爆款的句式上周不存在。静态标题库只能保证"及格线网感"，真正的网感必须写稿前**现扫**。本文件定义扫描流程。

## 一、何时启动

- 标题/钩子产出前（工作流第 4 环前置）
- 用户问「最近什么火」「这周哪类标题在涨」类趋势问题时
- 热点借势需求（用户明确要蹭）

## 二、扫描流程（三步）

### 第 1 步：定扫描源（按平台路由，国内外双渠道）
| 平台 | 扫描源 |
|---|---|
| 公众号 | 新榜/清博榜单、搜狗微信热搜、用户关注的同赛道头部号近 7 天推文 |
| 小红书 | 搜索下拉词、品类热榜、千瓜/新红数据（若用户有账号） |
| 知乎 | 热榜、圆桌、同领域高赞新回答 |
| 全网·国内 | 微博热搜、百度风云榜、抖音热点宝、即刻热门、头条热榜 |
| 全网·国外 | Reddit（r/artificial、r/LocalLLaMA、r/singularity）、Hacker News、X/Twitter 趋势、Product Hunt、Google Trends |
| 数据研究站 | Artificial Analysis、Semrush/BrightEdge/SparkToro 报告、ai0.news 等 AI 新闻聚合 |
| AI 搜索 | 把目标词直接问 ChatGPT/元宝/Perplexity，看 AI 引用谁的什么结构 |

### 第 2 步：提取活模式（3 个）
从扫描结果中提炼**本周在涨的表达模式**，每个模式记录：
```
- 模式：如「反向种草（先说缺点再推荐）」
- 样本：2-3 个真实爆款标题/开头（带来源链接或出处）
- 数据信号：点赞/阅读/排名量级
- 适配性：与用户账号定位和人设的匹配度（高/中/低）
```

### 第 3 步：融合产出
- 把活模式与 title-hook-library.md 的静态公式**杂交**：静态公式保结构，活模式保新鲜度
- 产出标题时标注哪个元素来自活扫描（如「反向种草结构 ← 本周新榜 Top10 中 3 篇在用」）

## 三、纪律

1. **扫不到就标【待核实】**：无法访问榜单/用户没提供样本时，明说"我目前扫不到实时榜单"，给静态库方案 + 请用户提供 3-5 篇近期看到的爆款。
2. **不编造趋势**：禁止凭训练记忆说"最近流行 XX"——训练数据有截止日期，趋势判断必须有近 7 天样本。
3. **只取模式，不抄内容**：提取的是表达结构与钩子类型，绝不照搬具体文案（版权红线，见 compliance.md）。
4. **热点要过中长周期筛**：扫描发现的热点，默认只借「表达模式」不借「时效话题」；除非用户明确要蹭，且必须按规则优先级提示短生命周期风险。

## 四、与归因节奏联动

网感雷达发现的模式如果带来了数据异常值（某篇打开率显著高于均值），在每周归因（attribution-rhythm.md）时沉淀进 style-anchors.md，让"扫描到的活模式"转化为"你账号验证过的有效模式"。
