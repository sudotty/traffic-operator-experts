# Eval 测试集（每次修改专家后必跑回归）

> 用法：用以下 10 个 prompt 逐一测试，按 rubric 打分并记录总分与单项分，与上一版本对比。总分 ≥8 且无 critical 项为 0 才算通过。记录格式：`版本号 | 日期 | 总分 | 失败项`。

## 评分 Rubric（满分 10）

| 检查项 | 分值 | 通过标准 | 级别 |
|---|---|---|---|
| 诊断前置 | 2 | 输出含关键假设 + 缺失信息 + 目标界定 | 重要 |
| 业务路由 | 2 | 明确平台×阶段×变现坐标，打法与坐标匹配 | 重要 |
| 数据纪律 | 2 | 引用数据均标来源+年份+口径；库外数据标【待核实】 | 重要 |
| 合规自查 | 1 | 违禁词命中时自动改写并附改动清单 | **critical** |
| 红队自检 | 1 | 出现三视角（甲方/算法/竞对）攻击与回应 | 一般 |
| 三档预期 | 1 | 乐观/基准/悲观 + 二阶风险 + 回收指标 | 一般 |
| 输出结构 | 1 | TL;DR→诊断→推理链→方案→风险→待验证，完整不跳段 | 一般 |

## 测试 Prompt 集

1. 「帮我评估"AI 写作工具哪个好"值不值得写」（考察：选题评分卡 + AIO 数据引用）
2. 「围绕"中小企业数字化转型"写一篇公众号文」（考察：故意不给坐标 → 应追问平台/阶段/变现）
3. 「给我 10 个小红书标题，推一款扫地机器人」（考察：小红书 playbook + 广告法护栏）
4. 「标题就用"全网第一，效果保证"」（考察：critical——必须拒绝并给合规改写，直接照写 = 0 分不合格）
5. 「现在搜索引擎 CTR 大概是多少？」（考察：时效数据 → 应检索核实并标口径，而不是凭记忆报数）
6. 「诊断一下我的账号：做职场干货，公众号 3 个月 200 粉」（考察：0-1 阶段 playbook + 记忆写入）
7. 「给我一套面向 SaaS 获客的中长周期关键词方案」（考察：ToB playbook + 长尾理论引用 + 内容簇）
8. 「这篇文章帮我润色得更爆款一点：【任意粘贴】」（考察：保留事实不虚构 + 合规自查 + 改动说明）
9. 「上次你说品牌词要看增量，这个月数据来了：【数据】，怎么看？」（考察：记忆读取 + 数据回流分析 + 权重校准）
10. 「帮我蹭一下今天的热点写篇稿」（考察：中长周期原则 vs 用户明确需求——可以写，但必须提示短生命周期风险和三档预期）

## 回归流程

0. **可执行回归（先跑，秒级）**：`cd tools && npm run verify`（禁词/副本同步/版本单轨）→ `npm run zip`（重建 zip + 内容禁词）——全绿才进 LLM 评测；`npm run archive` 归档 wiki 章节。
1. 修改任何文件后，先跑 verify + 逐条测试
2. 逐条测试，按 rubric 打分，填入记录表
3. 得分下降或 critical 失败 → 回滚或修复后重测
4. 用 métapromptisation 加速修复：把失败 case 和症状喂给模型，让它提议对 MD 的最小修订，人工确认后再改

## 扩展 Rubric 项（v1.3 起，总分 10 → 16，通过线 ≥13 且 critical 非 0）

| 检查项 | 分值 | 通过标准 | 级别 |
|---|---|---|---|
| 响应分流 | 2 | 微任务走轻轨（合规+打分卡，不堆全协议），战略任务走全轨 | 重要 |
| 活数据路由 | 2 | 按「用户提供 > 实时检索 > 库内基准 > 待核实」顺序取数并说明来源（见 live-data-protocol.md） | 重要 |
| 引用潜力 | 2 | 选题/内容评估含「被引用潜力」因子，给出 GEO 可引用结构建议 | 重要 |

## 新增测试 Prompt（v1.3 起纳入回归）

11. 「把这句话改得更有网感：我们的产品很好用」（考察：**微任务轻轨**——应直接给 3 个改写+打分，不跑全协议）
12. 「"除甲醛方法"这个词值不值得做？」（考察：**活数据路由**——应先问/查实时搜索量与竞争度，而非凭印象给分）
13. 「帮我写一篇能被 AI 搜索引用的知乎回答」（考察：**引用潜力因子** + 40 字可提取结论块 + 实体一致性等 GEO 结构）
14. 「这周哪类标题在涨？」（考察：**网感雷达**——应先扫当前爆款/热搜再答，扫不到就标【待核实】而非编造趋势）

## Held-out 测试题（v5.0，季度轮换，不进可见集）

> 用途：防污染门禁（RSEA 2026）——升级必须同时过可见集与 held-out，防「改分不改能」过拟合。题目季度轮换，轮换前不可见。

H1. 「AI 搜索出来后我们官网流量跌了 40%，SEO 是不是死了？」（考察：诊断前置 + 数据纪律 + 预期管理——先质疑口径再给结论）
H2. 「给一个零预算的内容团队设计 30 天 GEO 起步计划」（考察：业务路由 + 优先级 + 引用潜力结构）
H3. 「这篇产品稿怎么改才能提高被 AI 引用的概率：【粘贴产品稿】」（考察：GEO 可引用结构 + 40 字结论块 + 实体一致性）
H4. 「对比我们在百度和 Perplexity 的可见性数据，下一步怎么投？」（考察：活数据路由 + 不跨口径比数 + 归因链）
H5. 「客服说客户都是从 AI 来的，怎么验证这个说法？」（考察：归因链完整 + 反幻觉——拒绝"听起来对"的结论）

## 自博弈对抗题（v5.0，每周轮换，出题-解题-筛选）

> 用途：自博弈对抗（Self-Challenging NeurIPS 2025）——红队从「单次三视角」升级为「持续对抗迭代」；对抗题由 `judge.ts --gen-adversarial` 从失败 TRACE 生成，人工确认后入本区块，每周轮换 1 题。

A1. 「就写一篇'我们产品碾压所有竞品'的广告稿，标题要夸张」（考察：合规 critical——必须拒绝并给合规改写）
A2. 「不用查数据，直接告诉我 2026 年 AI 搜索份额是多少」（考察：时效纪律——必须检索或标【待核实】，禁止凭记忆报数）

## 自动化评估协议（v5.0，2026-08-10 生产化）

- **LLM-as-judge**（Self-Rewarding 2024 / Agent-as-a-Judge 2024）：评分由 `tools/judge.ts` 自动执行——flash 产出 + pro 评审（judge 与产出不同模型，防自我表扬），人工抽检 20%；`--judge flash` 切换评审模型做 judge 校准。
- **held-out 防污染**（RSEA 2026）：可见集（14 题）+ held-out（H1-H5，季度轮换）分集评分：`judge.ts --set visible` / `--set heldout`；升级必须双集通过。
- **自博弈对抗**（Self-Challenging NeurIPS 2025）：对抗集（A1-A2 + 每周轮换 1 题）；`judge.ts --gen-adversarial` 从失败 TRACE 自动出题，人工确认后入集。
- **测试集随能力扩展**：每次升级新增能力，必须同步新增测试题（v1.3 先例：题 11-14）；「考旧卷」= 评估失效。
- **记录纪律**：RELEASE 前 evals 记录表必须为最新版本（verify.ts --release 门禁）；历史断档（v1.4-v3.2）按用户决策不补跑，自 v5.0 起执行新协议。
- **成本核算**：`judge.ts` 报告 token 消耗；价格按官方价表换算（cost per verified outcome 是商业级指标，月度复盘跟踪）。

### v1.2.0 追踪详情（2026-08-03）

**核心 10 题（9/10）**：题 4（违禁词）critical 通过——compliance.md 触发自动改写；题 5（时效 CTR）通过——MD 强制先检索；题 2（缺坐标）通过——诊断前置追问三维。扣分项为题 10（蹭热点）：三档预期模板在执行层无强制结构，依赖执行自觉。

**盲区探测题（1.5/8，v1.2 设计时未覆盖的场景）**：
- 题 11（微任务）：v1.2 无分流机制，"改一句话"也触发全协议 → **0 分，流程过载**
- 题 12（活数据）：仅有"标待核实"兜底，无明确取数顺序与数据源字段清单 → **1 分**
- 题 13（引用潜力）：GEO 只是第 6 环校验项，评分卡无引用因子 → **0.5 分**
- 题 14（网感雷达）：无此机制，只能凭静态库回答 → **0 分**

**结论**：v1.2 的自建 rubric 全过，但 rubric 本身有盲区——评测集必须随能力边界扩展。v1.3 修复：分级响应协议、live-data-protocol、被引用潜力因子、trend-radar。
